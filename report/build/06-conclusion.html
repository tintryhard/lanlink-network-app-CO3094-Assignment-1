6 Conclusion

LanLink provides authenticated private and public chat, an online user list and file transfer through a central server. Clients keep a TCP connection for their session, use TLS when communicating across the LAN, and can find the server through optional UDP discovery. File transfers include recipient approval and checks of the received size and SHA-256 digest before completion is confirmed.

Building the application showed how much coordination is needed above the transport layer. The application must define message boundaries, match replies to requests, protect shared state and handle interrupted connections without leaving unfinished transfers behind. Separating the interface, networking and transfer logic made these behaviours easier to test. The automated tests cover framing, concurrent connections, authentication, file integrity and failure handling, while the terminal demonstration shows private chat, public chat and a completed file transfer.

The current version is intended for live communication between online users. Public messages are forwarded to recipients in sequence, discovery has no retry, and there is no heartbeat or storage for offline messages. Future work could improve connection monitoring, make discovery less sensitive to packet loss and reduce the effect of a slow recipient on public chat. These improvements would extend the existing design without changing the basic client-server model.
