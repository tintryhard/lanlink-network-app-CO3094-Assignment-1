D Locks and lock order

Table 12 lists the locks, what each protects and whether it is held during socket I/O.

Lock Defined in Protects Held during socket I/O
TCPServer._lock server/app.py:72 the registries _connections, _users, _transfers; connection state; transfer status and deadline; the atomic check-and-insert at login never while a thread reads or writes a socket or hashes a password (the accept loop does close an over-cap socket and start a worker under it, server/app.py:148-161)

Order on the server: a thread may hold a TransferSession.lock while it takes TCPServer._lock or a _write_lock, never the reverse. TCPServer._lock is never held while a transfer lock or a write lock is taken (server/app.py:393), and _write_lock is innermost: under it the thread only calls sendall(). On the client, the shared lock (PrivateChatClient._lock) and the engine RLock are never nested; engine callbacks run only after the engine lock is released (see transfer/progress.py). Apart from taking those two inner locks and writing, a thread that holds a transfer lock blocks only on the event Connection.auth_ready, for at most 1 s (AUTH_READY_WAIT_S), until the recipient's AUTH_OK has been sent.
